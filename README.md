# Corte Plugins

First-party plugins for the [Corte](https://corte.so) marketplace — and the
reference for building your own. Corte is an AI media platform; plugins extend
its editor with agent tools, shader effects, templates, stock libraries, and
model catalog entries, installed by users from **Settings → Marketplace**.

Every plugin here is real, published, and deliberately written to be read.
If you're building a plugin, start by copying the one closest to what you're
making.

## Anatomy of a plugin

A marketplace plugin is **two artifacts**, both generated by the build:

1. **`dist/manifest.json`** — the published contract: id, version, permissions,
   and every contribution. Templates, stock, effects (GLSL + declarative
   uniforms), and model cards are *pure data* and need nothing else.
2. **`dist/plugin.js`** — a self-contained ES-module bundle, only when the
   manifest declares agent tools. It runs in a **sandboxed worker**: no DOM, no
   app internals, no network unless the manifest requests `net:fetch`. Every
   editor call crosses a message boundary where the user's granted permissions
   are enforced.

Both come from one source of truth: `src/manifest.ts` (typed via
[`@corte/plugin-types`](packages/plugin-types)) and `src/plugin.ts`. The shared
build (`scripts/build-plugin.mjs`) refuses to emit artifacts that drift —
a declared tool without a handler, a handler without a declaration, mismatched
versions, or a contribution id outside the plugin's namespace all fail the build.

```
plugins/<name>/
├── package.json        # build + typecheck scripts
├── src/
│   ├── manifest.ts     # the contract — defineManifest(...)
│   ├── plugin.ts       # the sandbox bundle (only if the plugin ships tools)
│   ├── <logic>.ts      # pure logic, kept testable
│   └── <logic>.test.ts
├── assets/             # icon, screenshots, media — served via raw.githubusercontent
└── README.md
```

## Building

```sh
npm install
npm run build        # every plugin → dist/manifest.json (+ dist/plugin.js)
npm test             # unit tests for the pure logic
npm run typecheck
```

## Publishing

One command publishes everything that changed:

```sh
CORTE_API_KEY=corte_sk_…  npm run publish              # all plugins
npm run publish -- beat-match film-lab                 # just these
CORTE_API_URL=http://localhost:8787 npm run publish    # against a dev server
```

For each plugin it rebuilds (so drift fails before anything ships), compares
the local `pluginVersion` against the marketplace, and publishes only what's
**new or ahead** — up-to-date plugins are skipped, and a local version *behind*
the marketplace is reported, never silently re-published. Bundles upload
automatically; the price comes from the plugin `package.json`'s
`corte.priceCredits` (omit to keep the current price — authors earn 70% of
every sale in credits). API keys come from **Settings → Developer → API**.

Manual alternative: **Settings → Developer → Plugins → Publish a plugin…** —
paste `dist/manifest.json`, attach `dist/plugin.js`. Each publish is a new
immutable version.

### CI publishing

Merges to `main` publish automatically via
[`.github/workflows/publish.yml`](.github/workflows/publish.yml): the same
version-diffing publisher runs with `CORTE_API_KEY` from the repo's Actions
secrets — encrypted, masked in logs, and never exposed to workflows from fork
PRs (which only run the secret-free [CI workflow](.github/workflows/ci.yml)).
Release flow: bump a plugin's `pluginVersion`, open a PR, merge — CI publishes
exactly the bumped plugins and skips the rest.

See [docs/authoring.md](docs/authoring.md) for the full walk-through, and the
[plugin guide](https://help.corte.so/developers/plugins) for platform docs.
